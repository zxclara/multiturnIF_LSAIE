**Synthetic Instruction-Following Data Generation Plan**

1. **Seed Extraction**
Use all single-turn samples (~30k) from the ***allenai/tulu-3-sft-personas-instruction-following*** dataset as seeds. Each seed contains a user query and an assistant’s answer.
2. **Plan Generation (per seed)**
For each seed:
    - Use **Qwen/Qwen3-32B** for now (planner/responder/evaluator); keep the interface so we can swap model names later.
    - Based on the paper https://arxiv.org/abs/2501.17399, provide the model with:
        - Descriptions of four multi-challenge task types,
        - Detailed goals within each task,
        - Possible trap mechanisms.
    - Ask the model to:
        1. Select the most suitable task type for the seed.
        2. Produce a trap-aware conversation plan (including trap design and evaluation criteria).
        3. Generate **15** natural, context-linked turns simulating a real multi-turn dialogue.
        4. Describe how to detect whether the responder falls into the trap (and how to tell if the trap actually appeared in the dialogue).
    - Use high temperature for diversity.
    - Produce **4 independent plans per seed**.
3. **Trajectory Generation (per plan)**
For each plan:
    - Randomly select a responder model from the same model pool.
    - Feed the plan step-by-step, allowing the responder to see the seed’s ground-truth answer.
    - Collect simulated answers for all turns.
    - Produce **4 trajectories per plan**, resulting in **16 trajectories per seed**.
4. **Trajectory Evaluation**
    - Choose the strongest available open-source model as the evaluator.
    - For each trajectory, ask the evaluator to:
        1. Determine whether the trap was present in the dialogue (otherwise mark as incomplete),
        2. If present, determine whether traps were triggered,
        3. Score the trajectory on *naturalness*, *authenticity*, *safety*, and *accuracy*.
    - Among trajectories that avoided traps, keep the **top 2** by score.
5. **Success-Rate Monitoring & Regeneration**
    - Track the rate of trap-free, high-scoring trajectories.
    - If the success rate is low, re-invoke the responder model with access to:
        - Failed trajectories,
        - Trap explanations,
        - Reasons for failure.
    - Regenerate the problematic response turns.
6. **Final Dataset Size**
Following the above pipeline, expect to collect **up to ~60k high-quality, diverse multi-turn instruction-following conversations**, each grounded in a real seed but expanded with trap-aware reasoning and evaluation.

7. **Output Format and Logging**
    - Emit Alpaca-style entries with a `messages` array (user/assistant alternation) plus metadata: planner plan text, trap description, plan id (per-seed index), planner/responder/evaluator model names, `source_id` from the seed, and a generated id of the form `{source_id}_{n}`.
    - Persist intermediate artifacts:
        - Hugging Face seeds cache under `hfdata/`,
        - Plans under `generated/plans/`,
        - Dialogues and evaluations under `generated/dialogues/`.
    - Keep detailed logs and run-level stats for provenance and debugging.

8. **Initial Run Scope**
    - Start with **10 seeds** to validate the pipeline end-to-end before scaling.
